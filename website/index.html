Mock-up: Hytte Monitoring with micro:bit

1. About this project

This is a mock-up of a cabin monitoring system, made for a school course on model-driven design. We first drew the system as UML diagrams. Then we built a small part of it on a BBC micro:bit.

It is a mock-up for learning, not a working product. Most of the system exists only in our design and code.

2. What the website has

Dashboard: shows what the micro:bit reports, such as the mode, alarms and a simple history.

Install firmware: how to put our program on a micro:bit.

3. How it works

The micro:bit is connected to a computer with a USB cable. When something happens, it sends a short message. The dashboard reads these messages and saves them in the browser. There is no server.

On the board:

  • A and B together: switch between HOME and AWAY
  • A: the door opens (a warning in AWAY)
  • Shake: smoke (a critical alarm)
  • B: mark the newest alarm as resolved
  • Touch the logo: shown as "water leak"

4. What we planned and what we built

Our plan had eight sensors, alerts to family and emergency services, frost protection, and battery and SIM backup. A micro:bit has only two buttons and a few simple sensors, so we built much less:

  • The door and smoke alarms work, with HOME and AWAY.
  • Temperature, sound and "water" are only shown, not used for alarms.
  • Escalation, frost protection and backup exist only in our code, not on the board.
  • There are no phone messages.

5. How we worked

We drew the design first, let an AI write the code from it, and used a tool to compare the code with the diagrams. The chart shows how that comparison changed over nine steps. The code and our notes are on GitHub.

The checking tool is not ours. It comes from our course's template, ModelDrivenDesign_ex2, and we copied these parts into our repository:

  • tools/: the verifier, which reads our diagrams and the C++ code and compares them. It gives the same result every time, so the check is deterministic.
  • examples/: worked examples, which we used to learn how the tool works.
  • AGENTS.md: the rules the AI follows when it turns diagrams into C++.
  • The VS Code tasks, and the micro:bit build script, which we adapted.

To run it, we installed Python with the libclang library, and clang. Building for the micro:bit also downloads the Arm compiler and the micro:bit's own libraries (CODAL).

Where our diagrams were unclear, we checked our team guide. Where that did not settle it either, the AI made an assumption. Those assumptions were not final: our team went through all 13 of them, kept 10 and changed 3.

6. Trying it

You need a micro:bit v2, a USB cable and Chrome, Edge or Firefox 151 or newer. Start with Install firmware, then open the Dashboard.
